10.2 Why automatic OAuth could not work
- GitHub's protected-resource metadata points to the issuer
  https://github.com/login/oauth.
- The RFC 8414 metadata at
  https://github.com/.well-known/oauth-authorization-server/login/oauth lists
  the authorization, token and device endpoints but no registration_endpoint.
- OpenCode's MCP OAuth client requires dynamic client registration, so
  `opencode-v2 mcp auth github` reports "not an OAuth-capable remote server"
  and the earlier attempt failed with "does not support dynamic client
  registration". This is a limitation on GitHub's side, not a config error.

10.3 What was done
1. Installed GitHub CLI 2.105.0 with winget (package GitHub.cli).
2. Ran `gh auth login --web` with scopes repo, read:org, read:user, gist,
   workflow. The one-time device code 6959-F598 was approved in the browser.
   Result: logged in as vijayaragavan-dev; token stored in the Windows keyring.
3. Moved the token into the user environment as
   GITHUB_PERSONAL_ACCESS_TOKEN without printing it, and persisted it with
   `opencode-v2 service set env GITHUB_PERSONAL_ACCESS_TOKEN`.
4. Set the github entry to "disabled": false. The header remains
   "Authorization: Bearer {env:GITHUB_PERSONAL_ACCESS_TOKEN}"; no token was
   written to opencode.jsonc.
5. Restarted the background service. `mcp list` reports github connected and
   a live get_me call succeeds.

10.4 Root cause of the first failure
The background service had been started before the variable existed. Windows
process environments are fixed at creation, so the header resolved to
"Bearer " and the endpoint returned 400 "Authorization header is badly
formatted". A user-level setx alone is not enough for a running service; the
service must be restarted with the variable, and `service set env` makes it
survive later restarts.

10.5 Security note
- `opencode-v2 service get` prints service environment values in plain text.
  It exposed the token once in this session's tool output. The token is not in
  the repository, opencode.jsonc, this report or any project file, but it
  should be treated as exposed to the session log and the model provider.
- Recommended rotation if that log is shared: `gh auth logout --hostname
  github.com`, repeat the device login, then repeat the setenv and
  `service set env` steps.
- The token has repo scope and can read and write the user's repositories.
  Treat it as a credential, not a public identifier.

11.3 Architecture decision
The universe uses CSS 3D rather than a second React Three Fiber canvas.
This keeps a single WebGL context for the existing left constellation,
avoids competing with lib/webgl-lifecycle.ts, reuses the existing
brandIcons/TechIcon data, and adds no npm dependencies.

11.5 Accessibility
- Stage exposes role="group" with a category-specific accessible name.
- Every object is a real button with an aria-label; learning objects say
  "— learning".
- Selection uses aria-pressed and is announced through an aria-live readout.
- Visible focus ring; keyboard hint is available to screen readers.
- Decorative SVG marks are aria-hidden and not focusable.
- Hover/focus labels are aria-hidden because the button already names the
  technology.
- prefers-reduced-motion removes float, drift, entry, ring and transition
  animations.
- Touch targets are expanded to at least 44px effective size for the
  smallest/deepest objects; empty-stage vertical swipes still scroll the
  page while horizontal drags orbit the universe.
